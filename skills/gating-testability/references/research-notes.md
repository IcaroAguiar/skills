# Research Notes

These notes summarize external research used to shape this skill. Keep them
short and update only when the research changes the gate.

## UI And Browser Testing

- Testing Library emphasizes user-like tests: confidence grows when tests
  resemble real software use.
- Playwright best practices prioritize resilient locators and trace/debug
  artifacts for failure analysis.
- Playwright locator docs warn that long CSS/XPath chains are brittle; prefer
  role, label, text, and stable test-id locators.
- Playwright assertions auto-retry web-specific expectations, which is more
  reliable than arbitrary sleeps.
- Playwright visual comparisons support deterministic screenshot expectations
  and snapshot review.
- Vitest Browser Mode exists because simulated DOM environments can produce
  false positives or negatives for browser behavior; CI-grade usage should use a
  real browser provider such as Playwright or WebdriverIO.

## Contract And CI Evidence

- Pact frames contract testing as code-first consumer-driven checks generated by
  automated consumer tests and verified as concrete request/response examples.
- GitHub Actions artifacts are the right place to persist build/test outputs,
  including logs, test results, screenshots, coverage, and performance output;
  dependency caches are for speed, not evidence.
- Nx affected commands use git history plus the project graph to identify
  changed projects and dependents, but root/shared changes may still expand the
  affected set.

## Implications For This Skill

- Browser exploration should be promoted into deterministic tests where
  practical.
- Visual changes need screenshot/trace artifacts, not prose-only assertions.
- Monorepo gates should use affected graph evidence but escalate when the graph
  is unclear or shared surfaces changed.
- Contract changes need consumer/provider or schema/client compatibility checks;
  provider unit tests alone are not enough.
- Final answers must include evidence artifacts that reviewers can inspect.
