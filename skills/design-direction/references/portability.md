# Portability

Keep the conceptual core independent of technology and harness. Adapt implementation to the discovered stack without placing CSS, Tailwind, React, Next.js, shadcn/ui, React Native, or product-specific tokens in authorial rules.

## Universal invariants

Every adapter must:

- apply the same foundations to creation and review;
- preserve product profiles and surface modes;
- separate evidence, inference, requirement, and preference;
- require approval before incorporating a preference;
- preserve the user's output language;
- issue verdict and residual risk for reviews;
- allow distinct visual identities across projects.

## Codex

Keep `SKILL.md`, `agents/openai.yaml`, and `references/`. Invoke as `$design-direction`. Use code, browser, image, or Figma capabilities only when the task needs them.

## Claude Code

Use a thin adapter that describes triggers, loads only relevant references, follows repository-local instructions, adapts implementation to the stack, and preserves verdict semantics. Product-specific Codex metadata is not a universal instruction.

## Cursor

Expose the same trigger description, branch routing, reference paths, verdict
semantics, and output templates. Treat editor, browser, image, and terminal
capabilities as discovered tools rather than requirements of the conceptual
core.

## Generic agent

Provide the trigger description, precedence, context classification, selected branch workflow, relevant reference modules, and output template.

## Parity test

Run the same request and raw artifact through two harnesses. Compare:

- product profile and surface mode;
- fundamental violations;
- positive-pattern preservation;
- finding priority;
- verdict;
- redesign structure.

Language variation is acceptable. Divergence in foundations, priority, or surface mode requires adapter correction.
