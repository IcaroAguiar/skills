# Referências visuais

Usar referências para entender decisões, não para copiar interfaces.

## Método de análise

```text
O que funciona:
Por que funciona:
Princípios extraídos:
Elementos específicos do contexto:
Riscos de reprodução:
Aplicações possíveis:
```

Separar observação de interpretação. Considerar produto, conteúdo, plataforma, densidade e tarefa antes de generalizar.

## Referências iniciais

- Carbon Design System — Structured List: https://carbondesignsystem.com/components/structured-list/usage/
- Carbon Design System — Contained List: https://carbondesignsystem.com/components/contained-list/usage/
- Apple Human Interface Guidelines — Layout: https://developer.apple.com/design/human-interface-guidelines/layout
- Material Design 3 — Cards: https://m3.material.io/components/cards/overview

Usar as referências oficiais para estudar listas estruturadas, composição, adaptação e o papel limitado dos cards. Confirmar URLs e conteúdo atual antes de citá-los como prova.

## Termos úteis de pesquisa

- `flat section-based application UI`
- `low-elevation enterprise interface`
- `settings page section dividers`
- `single-surface application layout`
- `structured metadata list UI`
- `content-first dashboard`

Evitar usar `modern SaaS dashboard`, `beautiful admin dashboard` ou `premium dashboard UI` como única direção; esses termos tendem a produzir soluções genéricas, cardificadas e decorativas.
