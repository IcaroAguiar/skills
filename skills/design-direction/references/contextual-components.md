# Contextual Components

Choose components from task structure, not from library availability.

For each material component record:

```text
Component:
Function:
Behavior:
States:
Platform variation:
Justification:
Rejected alternative:
```

Consider quantity, frequency, comparison, depth, reversibility, risk, platform,
screen size, and input behavior.

Examples:

- Use a timeline for operational events whose order changes the next action.
- Use compact rows for repeated comparable records.
- Use an object carousel only for a small set of visually distinct peers.
- Use a selection list when options need explanatory copy.
- Use a sheet for short contextual work; use a dedicated screen for deep work.
- Use a persistent action area only when the current state continuously
  determines one dominant next action.
- Use contextual menus for rare secondary operations.

Do not approve “use familiar components” as a sufficient specification.
Familiarity lowers learning cost; authored integration still requires product
type, density, state, focus, material, and motion.
