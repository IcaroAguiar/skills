# Product Context and Surface Mode

Classify two levels separately:

1. **Product profile:** SaaS, analytical dashboard, internal system, landing page, institutional site, mobile application, or isolated component.
2. **Surface mode:** operational, analytical, transactional, editorial/informational, or persuasive.

The product defines the ecosystem. The surface mode defines how the current page must work. A SaaS can contain a persuasive public page, transactional onboarding, an operational workspace, analytical reports, and editorial help.

## Mode signatures

| Mode | Dominant signals | Appropriate grammar |
|---|---|---|
| Operational | known task, repeated use, records, states, persistent navigation, shortcuts | compact task header, tools, lists/tables, stable action geography |
| Analytical | question, period, unit, comparison, filters, data quality | question-led header, global controls, evidence and comparisons |
| Transactional | bounded completion, requirements, validation, review, confirmation | clear progress where sequence is real, focused inputs, recovery |
| Editorial/informational | reading, authorship, measure, argument, references | expressive typography, reading rhythm, idea progression |
| Persuasive | positioning, proof, objections, conversion | headline, narrative sequence, proof, CTA |

## Landing-page drift

**Landing-page drift** or **marketing-site contamination** occurs when visual refinement turns a work surface into a promotional or editorial composition without a requirement change.

### Failure signals

- a task title becomes a slogan or promise;
- an operational PageHeader becomes a tall hero;
- acquisition copy or CTA displaces the work action;
- narrative bands reorganize content that users must locate and operate directly;
- expansive whitespace removes records, tools, or context from the first viewport;
- decision metrics become decorative impact numbers;
- persistent navigation, filters, states, or shortcuts disappear for visual cleanliness;
- promotional voice replaces precise domain language;
- recurring non-linear work is forced into presentation chapters.

### Preservation criterion

A redesign passes when:

1. users still recognize the same task and destination;
2. recurring data, actions, and navigation remain directly findable;
3. area utility is not traded for decorative hero space;
4. the PageHeader identifies the task before expressing personality;
5. domain language outranks promotional copy;
6. the surface mode changes only when the requirement changes.

## Product-profile adjustments

- **SaaS:** emphasize continuity, pending work, account state, and efficiency on operational surfaces; use persuasive grammar only on genuinely public or conversion-oriented surfaces.
- **Analytical dashboard:** lead with questions, definitions, period, unit, comparison, and data quality.
- **Internal system:** favor controlled density, keyboard use, predictability, exception handling, and traceability.
- **Landing page:** lead with positioning, proof, objections, narrative progression, and CTA.
- **Institutional site:** lead with trust, orientation, reading, identity, and access to services or information.
- **Mobile application:** establish the platform, device classes, task topology, input model, scroll owner, interruption model, and evidence devices; then apply [mobile-interfaces.md](mobile-interfaces.md).
- **Isolated component:** evaluate its responsibility and the page hierarchy it will enter.

**Complete when:** product profile and surface mode are independently justified, and the context lock preserves every element that would change the task if lost.
