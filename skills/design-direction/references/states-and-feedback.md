# States and Feedback

Every state indicator must answer:

1. State of what?
2. What is its scope?
3. Does it require action?
4. Is it persistent, transient, or historical?

Rewrite, relocate, or remove an indicator when those answers are unclear.

## State hierarchy

1. Global task or entity state.
2. Actionable alerts and pending work.
3. Local component or section state.
4. Transient feedback such as save or send.
5. Historical and administrative metadata.

Let urgency and required action determine emphasis. Different levels should not compete.

## Target composition

- Keep one primary global state near the page or entity context.
- Place local states beside their objects.
- Place save or submission feedback beside the relevant form or action.
- Place pending work where users can resolve it.
- Present metadata as a restrained structured line, list, or definition group.
- Name the object in state copy.
- Let actionable problems outrank positive confirmation.

## Fragmentation signals

- unrelated indicators lack perceptible order;
- global and local badges share equal weight;
- the same state repeats across regions;
- static metadata looks like an alert;
- vague copy such as “All good” omits the object;
- simultaneous indicators appear contradictory;
- passive positive status remains permanently prominent;
- version, date, or count receives its own status card.

## Verification criteria

- At most one primary global state is present.
- Each local state is adjacent to its object.
- Repetition has a functional reason and identical meaning.
- Static metadata stays visually subordinate.
- Actionable states outrank informational states.
- Positive confirmation does not compete with pending work.
- Global, local, transient, and historical information remain distinguishable.
- Simultaneous indicators do not create apparent contradiction.

State repetition is legitimate when distance creates context loss, regions have clearly different scopes, or accessibility or safety requires redundancy. Repeated state must declare scope and preserve meaning.

Before adding a badge, alert, or status block, ask:

- Does this information change the user's next decision?
- Is it already communicated?
- Is its scope evident?
- Does it need persistent emphasis?
- Would plain text or metadata communicate it better?

**Complete when:** every state has a clear object, scope, action requirement, duration, and proportionate emphasis.
