# Multi-Screen Coherence

When the brief describes a journey, produce the minimum screens or frames that
show:

1. entry;
2. selection;
3. depth;
4. action;
5. response;
6. completion or recovery.

For each screen record:

```text
Objective:
Dominant object:
Primary action:
Relationship to previous screen:
Visual-system variation:
Signature expression:
State demonstrated:
```

Cover applicable initial, loading, empty, partial, selected, pressed, focused,
editing, success, error, offline, unavailable, disabled, permission-denied,
long-content, and extreme-data states.

Share the system, not the layout. Reject a system where every screen is
`header + title + main card + list + button`.
