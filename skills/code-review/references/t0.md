# T0: deterministic pre-review

`scripts/review-t0.mjs` reviews the working tree (committed, staged, unstaged
and untracked changes) against its merge-base with the default branch, or with
`--base <ref>`. It runs
locally in seconds plus the time of the repository's own checks. Nothing runs in
hosted CI.

```bash
node scripts/review-t0.mjs -C <repo>                  # full T0
node scripts/review-t0.mjs -C <repo> --plan           # show the checks it would run
node scripts/review-t0.mjs -C <repo> --no-checks      # scanners only (~3 s)
node scripts/review-t0.mjs -C <repo> --base <sha> --wrap <queue> --json <file>
```

Exit `0` is `PASS`, `1` is `BLOCKED`, `2` is a usage or configuration error. The
JSON report is always written, to `--json` or `$TMPDIR/review-t0/<repo>-<head>.json`.
It ends with a route for the model tiers (below), and `head.tree` fingerprints
the working tree it checked, so `review-t1` can refuse a tree that changed since.
`PASS (incomplete: ...)` means a scanner was missing or no repository check was
found; `--strict` turns a missing scanner into `BLOCKED`.

## What runs

| Step | Reports | Blocks on |
| --- | --- | --- |
| Conflict markers | `<<<<<<<`/`>>>>>>>` on added lines | any |
| Manifest/lockfile | dependency fields changed without a lockfile change | never (warning) |
| gitleaks | secrets on added lines, and in every branch commit since the base; values are redacted | any |
| semgrep | `rules/` plus the repository's `.semgrep/` or `.semgrep.yml` | `ERROR` rules |
| osv-scanner | vulnerabilities in a changed lockfile that the base did not have | CVSS >= 7 |
| Repository checks | typecheck, lint, `lint:*`, affected tests | non-zero exit, timeout, or a changed working tree |

Scanners only report findings on added lines, so existing debt never blocks a
change. gitleaks scans every changed text file up to 20 MB; symlinks and binaries
are never read. Code rules also skip generated, vendored, minified and over-1 MB
files and the repository's `.semgrepignore`. Every skipped file is listed in
`skippedFiles`. Repository checks run whenever the diff is non-empty, including
deletion-only and rename-only changes. A missing scanner is reported as `?` and skipped; `--strict` blocks
instead.

Repository checks come from `.review-t0.json` when present, otherwise from
`package.json`: the first typecheck script, `lint` (or `check`), each `lint:*`
not already invoked by another lint script, and affected tests through
`vitest run --changed <base>` or `jest --changedSince=<base>`. Scripts that
rewrite files (fixers, formatters, `:update`/`:baseline`/`--update`/`--write`)
are skipped when that is statically visible: in the script's name, its command,
or anything it runs (named scripts, `run-p lint:*` wildcards, npm `pre`/`post`
hooks). What static detection misses is caught after the fact: T0 fingerprints
the working tree around every check and blocks with `modified` when it changed
(gitignored output is not covered). Test runners run with
`CI=1` (and `jest --ci`), so missing snapshots fail instead of being written.

T0 executes the repository's own scripts and reads `.review-t0.json`,
`.semgrepignore`, `.gitleaks.toml` and `.gitleaksignore` from the tree under
review, so a change can weaken its own checks: run it only on code you would
test locally, and review changes to those files like code. The report names the
check source. An invalid `.review-t0.json` stops T0 with exit 2.

```json
{
  "checks": [{ "name": "typecheck", "run": "pnpm typecheck" }],
  "tests": "pnpm exec vitest run --changed {base}"
}
```

`--wrap <cmd>` (or `REVIEW_T0_WRAP`) prefixes every repository check, for
example with a local job queue that limits concurrent heavy commands.

## Route

The report's `route`, printed as the `ROUTE` line, tells the model tiers what
this diff needs. It is computed from paths, so it is a starting point:

| Field | Value |
| --- | --- |
| `effort` | `medium` when every changed file is docs, tests, styles, locales, assets, lockfiles or generated; `xhigh` when a code path names an auth, tenancy, credentials or money area (`auth`, `session`, `rbac`, `role`, `tenant`, `secret`, `crypto`, `billing`, `payment`, ...) or is a migration or schema; `high` otherwise |
| `reasons` | the matched areas, with up to three files each |
| `t1` | whether the fast pre-pass runs: skipped for docs/tests-only changes and under 20 changed lines |
| `size` | `small` (under 50 reviewable lines), `medium`, or `large` (over 800 reviewable lines or 30 files). Reviewable lines leave out lockfiles, generated or vendored files, snapshots and pure renames (`reviewLines`, `reviewFiles`). Over the 400-line layer target or past `large`, a `SIZE` line gives the advice from [pr-size.md](pr-size.md). It never blocks. |

The report's `comments` counts the comment lines among the added source lines
(tests, lint directives and non-reviewable files left out). When there are at
least 10, they are at least 3% of those lines, and the diff removes fewer
comment lines from those files than it adds (`removed`), a `COMMENTS` line names
the files with the most; a cleanup that shortens comments gets none. It never blocks: the reviewer decides which ones stay,
under [review-standards.md](review-standards.md), Comments. Python docstrings
are not counted.

Paths cannot show a query filter that enforces tenancy or a contract another
service depends on: raise the effort when the diff reaches those, never lower it
below the route.

## Rules

| Rule | Lens | Catches |
| --- | --- | --- |
| `silent-catch-default` | contract | catch that turns any failure into an empty/default value |
| `await-in-loop-io` | perf | awaited query, request or authorization per loop item (N+1) |
| `unbounded-module-cache` | perf | long-lived Map/Set filled from request code with no eviction |
| `race-timeout-without-cleanup` | perf | `Promise.race` timeout that neither aborts the work nor clears the timer |
| `read-before-transaction` | contract | value read before a transaction and used inside it (TOCTOU) |
| `indexof-unchecked` | contract | `indexOf`/`findIndex` result used as a position without a `-1` check |
| `hard-truncate-text` | contract | fixed-length cut of human text |
| `regen-flag-without-ci-guard` | contract | env flag that rewrites expected output with no CI refusal |
| `xff-first-hop` | sec | client-chosen first `X-Forwarded-For` entry used as the client IP |
| `fs-path-without-containment` | sec | file access through a joined path with no containment check (hint) |

Rules are heuristics with `WARNING`/`INFO` severity: they direct the reviewer's
attention and never block on their own. The reviewer confirms or dismisses each
one. Rules declare `metadata.t0-suppress-if-file-matches` when a file-level
signal (an eviction call, a CI guard, a `realpath` check) proves the risk is
handled.

To dismiss a finding in code, add `// nosemgrep: <rule-id> -- <reason>` on the
line where the reported finding starts, or on the line above it. To add a repository rule (for example a parity check between a permission
list and its mutations), put a Semgrep rule in the repository's `.semgrep/`
directory with a test file next to it; T0 picks it up automatically.

Rule tests: `semgrep --test --metrics=off rules/`. Script contract:
`node scripts/test-review-t0.mjs`.
